# Онлайн-деканат

Цифровой секретарь деканата. Решение кейса «Центр-инвест», хакатон UMIHack 2026.

**Команда:** Ключенко София

## Что делает
Студент загружает фото/скан (JPG, PNG) или одностраничный PDF своего документа и задаёт вопрос.
Сервис:
1. распознаёт текст (EasyOCR; у PDF с текстовым слоем — читает слой напрямую);
2. определяет тип документа (справка об обучении, заявление на академический отпуск, справка о практике);
3. извлекает поля в карточку: даты в формате `ГГГГ-ММ-ДД`, пропуски — «не найдено»;
4. находит графические подпись и печать (надписи «Подпись» и «М.П.» не считаются);
5. проводит предварительную проверку комплектности по Положению (`rules.md`);
6. отвечает на вопрос со ссылками на поля (`field:<ключ>`) и пункты Положения (`rule:N.N`);
   если ответа в документе и Положении нет — так и говорит;
7. отдаёт `results.json` в формате организаторов.

Окончательное решение о принятии документа принимает сотрудник деканата (п. 1.3).

## Установка (Windows, PowerShell)
```powershell
py -3.11 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```
Нужен Python 3.10–3.12: под Python 3.14 PyTorch (а значит и EasyOCR) пока не ставится.
При первом запуске EasyOCR один раз скачивает веса моделей в `~/.EasyOCR`.

## Запуск
```powershell
streamlit run app.py                                                     # интерфейс
python generate_results.py --kit . --out results.json --evaluate          # весь набор, текст из PDF
python generate_results.py --kit . --out results_ocr.json --source ocr --evaluate   # весь набор через OCR
python evaluate.py --reference reference_results.json --predictions results.json
python check_ocr.py documents/open-001.png                                # проверка, что OCR работает
```

## Стек
Streamlit, EasyOCR (PyTorch), scikit-learn, Pillow, NumPy, SciPy, pypdf, pypdfium2.
PDF рендерится через pypdfium2, отдельный poppler не нужен; `pdf2image` используется только как
запасной вариант, если pypdfium2 не установлен.

## Инструменты
Только бесплатные библиотеки, всё работает локально. Внешние API для OCR, извлечения полей
и генерации ответов не используются. Поля извлекаются регулярными выражениями и словарями,
ответы строятся по правилам из `rules.md`, без языковых моделей.

## Файлы
| Файл | Назначение |
|---|---|
| `app.py` | интерфейс: карточка полей, проверка, ответ, подсветка поля, «Скачать results.json» |
| `ocr.py` | EasyOCR + предобработка плохих снимков |
| `extractor.py` | поля, даты, подпись/печать по графике, автоопределение типа, области полей |
| `responder.py` | `validation` и `answers` по README организаторов |
| `rules.py` | разбор `rules.md`, поиск похожих пунктов |
| `document_types.json` | типы документов, ключи, подписи полей, пункты Положения |
| `generate_results.py` | пакетная обработка набора в `results.json` |
| `check_ocr.py` | диагностика OCR на одном или нескольких файлах |

## Метрики (открытый набор, 30 документов, 120 вопросов)
Режим `--source auto` (текст из PDF, подпись и печать — по PNG):

| Метрика | Значение |
|---|---|
| field_accuracy_macro | 1.0 |
| validation_exact_match | 1.0 |
| question_exact_match | 1.0 |

Режим `--source ocr` (всё по PNG через EasyOCR): _впишите после запуска команды выше._

## Бонусы
- **Автоопределение типа** по ключевым словам из `document_types.json` (30/30 на открытом наборе).
- **Плохие снимки**: поворот по EXIF, выравнивание наклона до ±30°, выравнивание освещения
  и бинаризация Отсу (тени), медианный фильтр (шум, блики), перебор вариантов, если
  уверенность OCR < 0.5, повороты 90/180/270°.
- **Новый тип без кода**: запись в `document_types.json` — тип появляется в списке, поля
  извлекаются по подписям, проверка и ответы ссылаются на его пункты.
- **Подсветка**: выбор поля показывает его на снимке (зелёная рамка — заполнено, красная —
  пусто, синяя — найденная подпись/печать).

## Ограничения
- OCR работает на CPU: первый запуск медленный (загрузка моделей), далее несколько секунд на страницу.
- Рукописный текст в полях и многостраничные PDF не поддерживаются (не входят в проверку v1.0).
- Подпись и печать определяются по цвету и форме: в наборе это цветные макеты. Чёрно-белая
  печать на чёрно-белом скане будет считаться отсутствующей (строгий режим: не уверены — `false`).
- Подлинность подписи и печати не проверяется (п. 2.3 Положения).
